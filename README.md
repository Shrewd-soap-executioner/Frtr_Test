# FRTR Test 🛡️

Комплексное клиент-серверное решение для выдачи, управления и мониторинга доступа к прокси-серверам (виртуальным машинам). Проект состоит из асинхронного REST API, интерактивного веб-кабинета пользователя и десктопного приложения.

## 🛠 Технологический стек

* **Backend:** FastAPI, SQLAlchemy (async), PostgreSQL
* **Background Tasks:** Celery, Redis
* **Frontend:** Vue 3, Vuetify 3 (Vite, TypeScript)
* **Desktop Client:** Python, PyQt6, Requests
* **Infrastructure:** Docker, Docker Compose
* **Real-time:** WebSockets

---

## 🚀 Быстрый старт

Вся серверная и веб-часть (API, база данных, брокер сообщений и фронтенд) полностью изолированы в Docker и запускаются одной командой.

### 1. Запуск инфраструктуры (Сервер + Сайт)

В корневой директории проекта выполните команду:

```bash
docker-compose up -d --build
```

После сборки и старта контейнеров будут доступны:

* **Личный кабинет (Vue):** `http://localhost:3000`
* **Серверный API (FastAPI):** `http://localhost:8000`
* **Документация Swagger:** `http://localhost:8000/docs`

### 2. Запуск десктопного клиента

Перейдите в папку десктопного приложения, установите зависимости и запустите интерфейс:

```bash
cd desktop
pip install -r requirements.txt
python main.py
```

## 🧪 Тестирование

Бэкенд покрыт асинхронными автотестами с использованием **pytest** и **httpx**. Для ускорения выполнения тестовый набор использует единый Event Loop и отдельную тестовую базу данных.

Для запуска тестов выполните команду внутри запущенного контейнера бэкенда:

```bash
docker exec -it proxy_backend pytest
```

### Покрытые сценарии

#### Регистрация и валидация

* Успешное создание нового аккаунта.
* Проверка валидации данных.
* Получение ошибки **HTTP 422** при несовпадении паролей.

#### Авторизация

* Успешный вход с корректными учетными данными.
* Получение ошибки **HTTP 401 Unauthorized** при неверном пароле.

#### Управление профилем

* Успешная смена пароля пользователя.
* Принудительная регенерация одноразового ключа доступа.

#### Безопасность и Desktop Flow

* Полный цикл подключения десктопного клиента.
* Выделение виртуальной машины после успешной авторизации.
* Проверка механизма одноразового использования ключа доступа.
* Получение отказа при попытке повторного использования уже активированного ключа.
* Корректное освобождение ресурсов и возврат ВМ в пул после отключения клиента.

## 📖 Сценарий использования (User Flow)

1. **Регистрация** — пользователь создает аккаунт на сайте.
2. **Активация** — фоновая задача Celery отправляет письмо с одноразовым ключом доступа на email.
3. **Личный кабинет** — при входе на сайт открывается WebSocket-соединение. Страница ожидает подключения приложения.
4. **Подключение десктопа** — пользователь вводит полученный ключ в PyQt6-приложение.
5. **Выдача ВМ** — бэкенд авторизует десктопный клиент, помечает ключ как использованный, выделяет прокси-сервер и мгновенно через WebSocket отображает данные виртуальной машины в браузере.
6. **Отключение** — при закрытии десктопного приложения клиент отправляет сигнал на сервер, освобождая ВМ для других пользователей. Статус подключения на сайте автоматически меняется на **«Отключено»**.
